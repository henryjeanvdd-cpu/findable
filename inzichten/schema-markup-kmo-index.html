Schema Markup voor KMO's: Waarom AI je bedrijf niet vindt (en hoe je dat fixt)

Schema markup is onzichtbare code die AI-platforms vertelt wie je bent. Zonder schema moeten ChatGPT, Gemini en Perplexity raden. En ze raden je niet.

Het probleem: AI-platforms zijn slim, maar niet helderziend

Stel je voor dat je een brochure over je bedrijf maakt, maar zonder naam, adres of beschrijving. Je legt hem op een tafel in een druk conferentiecentrum en hoopt dat iemand hem oppikt en begrijpt wat je doet. Dat is wat de meeste websites doen voor AI-platforms.

ChatGPT, Gemini en Perplexity lezen je website. Ze scannen je teksten, je pagina's, je afbeeldingen. Maar zonder schema markup moeten ze zelf uitvogelen: Is dit een restaurant of een cateringbedrijf? Zit dit bedrijf in Antwerpen of in Gent? Bieden ze renovaties aan of alleen advies?

In onze AI Visibility Benchmark België 2026 zagen we een concreet voorbeeld: een bedrijf werd door Gemini in de verkeerde gemeente geplaatst, simpelweg omdat er geen LocalBusiness schema op de website stond. Na implementatie van schema markup werd de locatie correct weergegeven.

Uit onze benchmark: Bedrijven zonder schema markup scoren gemiddeld 15-20% lager op Gemini dan bedrijven met correcte gestructureerde data. Het verschil op Perplexity is nog groter — schema is daar een basisvereiste voor vermelding.

Wat is schema markup precies?

Schema markup is een stukje gestructureerde code (in JSON-LD formaat) dat je toevoegt aan de <head> van je website. Het is volledig onzichtbaar voor je bezoekers, maar het vertelt zoekmachines en AI-platforms precies:

✓ Wie je bent (bedrijfsnaam, type, oprichters)
✓ Waar je zit (adres, gemeente, land, GPS-coördinaten)
✓ Wat je doet (diensten, producten, specialisaties)
✓ Hoe je bereikbaar bent (e-mail, telefoon, openingsuren)
✓ Wat je reputatie is (reviews, beoordelingen)
✓ Welke vragen je beantwoordt (FAQ)

Denk aan schema als je digitale identiteitskaart. Zonder die kaart kan een AI-platform je niet met zekerheid identificeren — en dan raadt het je simpelweg niet aan.

Welke schema types heeft een KMO nodig?

De meeste Belgische KMO's hebben drie tot vier schema types nodig. Hier is de prioriteitsvolgorde:

1. LocalBusiness (of een specifieker subtype)

Dit is de belangrijkste. LocalBusiness vertelt AI-platforms dat je een fysiek bedrijf bent met een locatie. Gebruik altijd het meest specifieke subtype: Restaurant in plaats van LocalBusiness, Dentist in plaats van MedicalBusiness, RealEstateAgent in plaats van ProfessionalService. Hoe specifieker, hoe beter AI je kan classificeren.

2. Organization

Organization beschrijft je bedrijf als entiteit: naam, logo, oprichtingsjaar, sociale media profielen. Door Organization en LocalBusiness te combineren geef je AI-platforms het volledige plaatje.

3. FAQPage

FAQPage schema laat je veelgestelde vragen en antwoorden structureren. Dit is bijzonder waardevol voor AI-zichtbaarheid, omdat AI-platforms deze vragen-en-antwoorden direct kunnen overnemen in hun responses. Gebruik echte klantvragen als basis.

4. Service (optioneel maar waardevol)

Als je meerdere diensten aanbiedt, beschrijft Service schema elke dienst apart — inclusief prijs, beschrijving en doelgroep. Dit helpt AI-platforms specifieke diensten aan te bevelen bij gerichte vragen.

Gemini is het meest gevoelig voor schema. Het platform leunt zwaar op het Google-ecosysteem en gebruikt LocalBusiness data direct in zijn antwoorden. Een ontbrekend of onvolledig schema leidt aantoonbaar tot fouten in Gemini's output.

Hoe ziet schema markup eruit?

Hieronder een vereenvoudigd voorbeeld van LocalBusiness + Organization schema voor een fictieve bakkerij in Mechelen. Dit is de JSON-LD code die je in de <head> van je website plaatst:

// Dit plaatst je in de <head> van je HTML <script type="application/ld+json"> { "@context": "https://schema.org", "@type": ["LocalBusiness", "Bakery"], "name": "Bakkerij Janssens", "url": "https://bakkerijjanssens.be", "email": "[email protected]", "telephone": "+32 15 12 34 56", "address": { "@type": "PostalAddress", "streetAddress": "Bruul 45", "addressLocality": "Mechelen", "postalCode": "2800", "addressCountry": "BE" }, "openingHoursSpecification": [ { "@type": "OpeningHoursSpecification", "dayOfWeek": ["Ma", "Di", "Wo", "Do", "Vr", "Za"], "opens": "07:00", "closes": "18:00" } ], "knowsAbout": ["artisanaal brood", "gebak", "taarten op maat"], "areaServed": { "@type": "City", "name": "Mechelen" } } </script>

Dit vertelt elke AI-platform in één keer: dit is een bakkerij, ze zitten op Bruul 45 in Mechelen, ze zijn open van maandag tot zaterdag, en ze zijn gespecialiseerd in artisanaal brood, gebak en taarten op maat.

Hoe implementeer je het?

WordPress

Installeer een plugin zoals Rank Math of Yoast SEO Premium. Beide ondersteunen LocalBusiness, Organization en FAQPage schema. Vul de velden in via de plugin-instellingen — geen code nodig.

Andere CMS'en (Wix, Squarespace, Webflow)

De meeste moderne CMS'en hebben een veld voor "custom code" in de head-sectie. Plak daar je JSON-LD script. Bij Webflow vind je dit onder Project Settings > Custom Code > Head Code.

Statische websites (HTML)

Voeg het JSON-LD script direct toe aan de <head> sectie van je HTML-bestand, voor de sluitende </head> tag.

Valideren

Na implementatie altijd testen met twee tools:

1. Schema Markup Validator (validator.schema.org) — controleert of je code syntactisch correct is
2. Google Rich Results Test (search.google.com/test/rich-results) — toont of Google je schema herkent en er rich results voor kan tonen

De 5 meest gemaakte fouten

1. Te generiek schema type

Gebruik nooit het generieke "LocalBusiness" als er een specifieker subtype bestaat. Een tandarts hoort "Dentist" te gebruiken, een restaurant "Restaurant", een makelaar "RealEstateAgent". AI-platforms kunnen je dan nauwkeuriger classificeren.

2. Inconsistente NAP-gegevens

Je bedrijfsnaam, adres en contactgegevens moeten exact overeenkomen op je website, in je schema, op Google Business Profile, op Clutch en op LinkedIn. "Straat" versus "Str." is al genoeg om AI-platforms te verwarren.

3. Schema zonder zichtbare content

Google vereist dat alles wat je in schema zet, ook zichtbaar is op de pagina zelf. Voeg geen FAQ-schema toe voor vragen die nergens op je site staan. Dit kan leiden tot een penalty.

4. Verouderde informatie

Seizoensgebonden openingsuren? Nieuw adres? Nieuwe dienst? Update je schema elke keer als er iets verandert. Verouderde data is erger dan geen data.

5. Geen FAQPage schema

FAQPage is het meest onderbenutte schema type. Het kost weinig moeite, maar het geeft AI-platforms kant-en-klare vragen-en-antwoorden die ze direct in hun responses kunnen gebruiken. Vooral ChatGPT maakt hier veel gebruik van.

Checklist: schema markup voor jouw KMO

☐ LocalBusiness schema met specifiek subtype (Dentist, Restaurant, etc.)
☐ Organization schema met naam, logo, oprichtingsjaar en sociale media
☐ FAQPage schema met minimaal 5 echte klantvragen
☐ Correct adres met gemeente, postcode en land (BE)
☐ Openingsuren ingevuld
☐ NAP-gegevens consistent met Google Business Profile
☐ Gevalideerd met Schema Markup Validator
☐ Getest met Google Rich Results Test
☐ Indexering aangevraagd in Google Search Console
